Cookies

This site sets no cookies at all, and the only thing it ever stores is the theme you pick. That is why you never saw a banner asking about them, and this page explains how to confirm that for yourself rather than trusting the claim.

Why there is no banner

Cookie banners exist because most sites store identifiers in your browser and use them to recognise you across pages, sessions and sometimes other websites entirely. Under the EU ePrivacy Directive and the GDPR, and under similar rules elsewhere, consent is required before storing or reading information on your device unless it is strictly necessary to provide the thing you asked for.

This site stores one word, and only when you ask it to: the theme you picked with the Light or Dark control, so the next page matches. That is strictly necessary to do the thing you asked for, which is the one case where the rules need no consent. Nothing identifies you and nothing is read back for any other purpose. There is no consent to collect, so a banner would be pure theatre. Showing one anyway would train you to click through consent dialogs without reading them, which makes the web slightly worse.

What is actually stored

Every storage mechanism a browser offers, and what this site puts in it
MechanismWhat this site stores
CookiesNothing
Local storageOne entry named theme, holding the word light or dark, written only when you press the theme control. Clear it and the site follows your system setting again
Session storageNothing
IndexedDBNothing
Cache storage / service workersNothing. There is no service worker
Web SQL, app cacheNothing. Both are obsolete anyway

Your browser will cache the HTML, the stylesheet and the images the way it caches any website, so pages load faster on a second visit. That is ordinary HTTP caching, it holds no identifier, and clearing your browser cache removes it.

What each page loads

Every page loads four small stylesheets, the typeface in four weights, two small scripts, one icon and its pictures, all from this same site. The study page's charts are drawn into the page itself. The tools page also loads one script for the tools and one JSON file listing the coordinates and names of the 241 brain regions.

That is the complete list. No fonts from Google, no scripts from a CDN, no analytics beacon, no embedded video, no iframe, no social widget, no image from another domain. Nothing on any page causes a request to a server I do not control, which means no other company learns that you visited.

The JavaScript that does run

Every page runs one small script, written for this project and served from here. It switches the theme when you ask, opens the menu on a phone, and fades sections in as you scroll. The tools page runs three more.

One simulates study designs so you can see how often a study of a given size would find a given effect. One lets you step through the analysis choices and see the result each combination gives. One draws the brain map and handles clicking and filtering.

All three run entirely inside your browser. None of them sends anything anywhere, and none of them remembers anything after you close the tab. Every number they show is computed on your own machine from data already delivered with the page. If you block JavaScript, every page still reads in full, the theme simply follows your system setting, and the tools page shows plain text instead of the interactive parts.

Check it yourself

You do not have to believe any of this.

Open your browser's developer tools, usually with F12 or Command-Option-I. Go to the Application tab in Chrome or Edge, or Storage in Firefox and Safari, and look at Cookies for this domain. It will be empty. Look at Session Storage. Also empty. Local Storage holds the single theme entry if you have pressed the control, and nothing otherwise.

Then open the Network tab and reload the page. Every request listed will be to this domain. If you ever see one that is not, something has gone wrong and I would like to know about it through the repository.

There is also an automated test in that repository which scans every built page and script for cookie calls, analytics code and off-site resources, and checks that the only storage call is the theme preference. It fails the build rather than letting this page become untrue.
